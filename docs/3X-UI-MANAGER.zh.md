## 1. 这是什么，以及你需要什么

### 1.1. 应用能做什么

3X-UI Manager 是 3x-ui 面板的**管理客户端**。它连接一个已经在运行的面板，
把网页面板大致能给的东西搬到你手机上：

- 带服务器和 Xray 状态、负载图表和在线客户端列表的仪表盘；
- 完整的**入站**管理——创建、编辑、启用 / 停用；
- **客户端**管理：配额、到期、分组、搜索与筛选、批量操作、分发链接和二维码、IP 记录；
- **节点**（主 / 从多面板架构）管理，包括 mTLS；
- 编辑 **Xray** 配置：出站、路由、负载均衡、DNS、日志，必要时还能一次编辑整份配置；
- 面板本身的**管理**：账号、API 令牌、邮件设置、重启；
- 面板数据库的**备份**；
- 关于问题的**本地通知**：客户端到期、配额用尽、端口不可达、Xray 停止、节点掉线。

### 1.2. 环境要求

| 项目 | 要求 |
|---|---|
| Android | 7.0 或更高（API 24） |
| 3x-ui 面板 | **v3.3.0 或更高**——这是面板开始接受 API 令牌认证的版本。部分能力在更晚的版本才加入，旧面板上不可用。已测试至 **v3.11.0** |
| 网络访问 | 手机必须能到达面板地址（直连、经 VPN 或通过反向代理） |

**建议让面板保持最新版本**——这样应用的每个板块都可用，也能获得面板自身的修复。
哪个功能与哪个版本对应，见[第 17 节](#17-面板版本兼容性)。当面板版本低于某项功能所需时，
应用不会隐藏相应板块：而是在板块内提示你的面板版本尚不支持，并建议更新。

### 1.3. 应用不能做什么

这**不是 VPN 客户端**。它不会把手机接入代理，也不会让流量经由代理——它只管理面板。
要真正使用连接，你需要一个普通的客户端应用（v2rayNG、Hiddify、Streisand 等）；
本应用可以帮你把链接或二维码交给它。

应用也不能在服务器上安装或部署面板——面板必须已经部署好。

## 2. 安装与更新

### 2.1. 从哪里获取

| 来源 | 链接 | 说明 |
|---|---|---|
| **F-Droid** | <https://f-droid.org/packages/net.yukh.xui> | 推荐：更新经由商店目录送达 |
| **GitHub Releases** | <https://github.com/yukh975/3X-UI-Manager/releases> | 手动下载 APK |
| **Obtainium** | 添加仓库 `https://github.com/yukh975/3X-UI-Manager` | 直接从 GitHub 自动更新 |

GitHub 的每个 release 附带**两个** APK。普通那个名为
`3x-ui-manager-<version>.apk`——装它就行。`fdroid.apk` 是给 F-Droid
构建服务器用的参考二进制，没有理由手动安装。

**如何读懂版本号。** 版本号由构建日期和递增的构建序号组成，以点分隔：
`26.10.28.80` 表示 2026 年 10 月 28 日的第 80 次构建。release 标签是同一串字符
前面加上 `v`（`v26.10.28.80`）。构建序号只增不减、从不清零，因此使用旧编号
（0.15.x）的安装也会把新版本当作普通更新。

### 2.2. 各构建版本的区别

应用有两个构建变体，唯一的区别是更新机制：

- **标准版**（GitHub、Obtainium）可以自行检查更新并提示安装；
- **F-Droid 版**不行，因为商店会自行更新应用，且 F-Droid 的规则禁止应用
  下载并安装自己的 APK。它甚至不携带对应的系统权限。

两个版本用同一把密钥签名，因此可以互相覆盖安装，无需卸载，也不会丢失数据。

### 2.3. 更新如何送达

标准版在启动时检查新版本，并弹出带有变更列表的对话框。文本会跟随界面语言：
选择俄语时显示俄语更新日志，而不是英文发布说明；中文版更新日志暂未提供，
界面会回退到英文。如果你跳过了好几个版本，对话框会显示已安装版本之后**每个**
版本的变更——最新的在前，各自位于“版本 … · 日期”标题之下。

你可以在**设置 → 检查更新**里手动检查（按钮位于更新通道选择器下方，见
[2.4](#24-更新通道)）；它已不在“关于”里。

关掉的对话框不会再弹出：应用会记住你拒绝的版本，之后启动时不再提示。
仪表盘上的版本卡片仍会作为提醒保留，而手动检查无论如何都会显示该更新。

F-Droid 版完全没有更新检查，“关于”中显示：“当前为 F-Droid 安装版——更新通过
F-Droid 目录推送。”

### 2.4. 更新通道

仅限标准版。**设置 → 更新通道**：

- **稳定版**（默认）——来自 GitHub、经过测试的公开发布版；
- **实验版**——预发布构建，一出炉即可获取；可能不稳定。

通道决定应用到哪里查找新版本，启动时和按下“检查更新”按钮时都是如此。

## 3. 连接面板

应用**使用 API 令牌**连接。不使用管理员登录名和密码——令牌既更安全，
也不会因改密码而失效。

### 3.1. 在哪里获取 API 令牌

1. 在浏览器中打开面板。
2. 进入**设置 → 安全 → API 令牌**（面板英文界面为
   *Settings → Security → API Token*）。
3. 创建一个令牌并复制它的值。

> **具有 `admin` 范围的 3x-ui 令牌就是完整的管理员权限。** 持有它的人可以在网页面板里
> 做你能做的一切。请像对待密码一样对待它；如果手机丢失，在面板里删掉该令牌，
> 应用就会失去访问权。

### 3.2. 连接表单

| 字段 | 填什么 |
|---|---|
| **名称**（可选） | 面板的名字，在面板切换器中代替地址显示。留空则显示主机名 |
| **面板 URL** | 含协议和端口的地址，例如 `https://panel.example.com:2053`。如果管理员设置了秘密路径（`webBasePath`），要包含进去 |
| **API 令牌** | 从面板复制的值。“显示令牌”可以让你核对是否完整粘贴 |
| **允许自签名 TLS** | 关闭证书校验。仅当面板使用自签名证书时启用——而且只对你自己的面板 |
| **订阅基础 URL**（可选） | 很少用到。应用会自己从面板设置里读取订阅地址；只有公开地址不同时才在这里设置——例如面板在反向代理后面：`https://host:2096/sub/` |

连接成功后配置就会被保存，之后应用会自动重连。

### 3.3. 连接失败时

- **“意外响应”类错误**（界面原文：*Unexpected response — check URL and base path*）——
  通常意味着应用收到的是 HTML 而不是 JSON。地址里少了
  `webBasePath`，或者反向代理用自己的页面做了应答时，就会这样。
- **证书错误**——打开“允许自签名 TLS”。
- **401，或“你的 API 令牌已失效”**——令牌在面板里被删除或禁用了；重新创建一个。
- **毫无响应**——检查手机能否到达面板地址（移动网络、VPN、服务器端的来源 IP 限制）。

## 4. 多面板

应用可以保存任意数量的面板，并在它们之间切换。

顶栏的 **⇄** 按钮打开已保存连接的列表（“面板”），在那里可以：

- **切换**到另一个面板——每个页面都会针对它重新加载；
- **添加面板**——打开一张空的连接表单；
- **编辑**已保存的面板——面板的“编辑”按钮打开“编辑面板”页面，字段与连接时
  相同，令牌已经填好；
- 对某个面板**退出登录**——应用会忘掉它的地址和令牌。

编辑面板时，名称和订阅基础 URL 会立即保存。如果面板 URL、令牌或 TLS 设置有变，
应用会先用一次面板请求验证新信息，验证通过后才保存。已被另一个已保存面板使用的
地址不会被接受：“另一个已保存的面板已使用此 URL”。

列表中的面板以其名称标注，没有名称时以主机名标注。当前活动面板也会显示在
标题栏中，不容易搞混服务器。对最后一个面板退出登录后，应用回到全新安装的
状态——同时会清除应用锁密码。

## 5. 应用锁

由于应用持有的令牌对服务器拥有完全访问权，你可以用密码把它锁起来。
在**设置 → 应用锁**下：

- **设置密码**——4 到 8 位数字；
- **使用指纹解锁**——指纹或面容，若设备支持；
- **移除密码**。

实际行为：

- 启动时，只有在已设置密码且保存的会话被自动恢复的情况下才会要求输入密码；
  如果你刚刚手动输入了令牌，则不会再要求；
- 把应用切到后台会重新上锁，但有 **30 秒宽限期**——快速切到别的应用
  （复制一个地址或看一个验证码）再切回来，不会要求输入密码；
- 用密码或生物识别都可以解锁。

## 6. 仪表盘

第一个标签页。它会自动刷新；下拉列表可立即刷新。

### 6.1. Xray 状态

卡片显示 Xray 是否在运行及其版本。按钮：

- **重启**——会短暂中断所有活跃的客户端连接，应用会就此提醒你。在面板 3.3.1
  及更新版本上，通常不需要靠它来让配置更改生效——见[第 10 节](#10-xray出站路由dns)；
- **停止** / **启动**。

按下之后，应用会在短时间内保持预期状态，避免滞后的轮询让按钮来回跳动。

### 6.2. 服务器指标

- **CPU**、**内存**、**磁盘**——以百分比显示；
- **网络 ↑ / ↓ 每秒**——当前速率；
- **连接**——TCP 和 UDP 计数；
- **负载 1·5·15 分钟**——系统平均负载。

**交换分区与服务器地址。** 如果服务器有交换分区，CPU、内存和磁盘旁边会出现
**交换分区**卡片——像其他卡片一样点按即可打开历史；没有交换分区就没有卡片。
服务器的公网地址会分别以 **IPv4** 和 **IPv6** 标注显示，而不是合并成一个地址。

### 6.3. 历史图表

指标块可以点按，打开一段时间范围的图表。间隔可切换（默认是“实时”的两分钟粒度）；
面板保留系统指标历史大约一周。数据来自面板——应用自己不存任何数据。

### 6.4. 在线客户端

在线计数可以点按，打开列表。如果面板接入了节点，列表会按服务器分组，
你能看到谁在主服务器上、谁在节点上。

### 6.5. 本月流量

当前周期内所有入站的流量总计，同样按服务器细分。它由各入站的计数器累加而来；
如果有入站不是按月重置，应用会给出提示——否则这个总和会把按月计数和
全程计数的数据混在一起。

### 6.6. 面板版本与 Geo 数据库

单独一张卡片显示面板版本，有可用更新时提供**更新**。旁边是 **Geo 数据库**
更新按钮（geoip / geosite）：面板会重新下载它们并重启 Xray。

## 7. 入站

### 7.1. 列表

每个入站是一张卡片：备注、协议、端口、流量计数、到期时间，以及页面打开期间的
实时 ↑ / ↓ 速率。开关用于启用和停用入站；如果面板拒绝了操作，应用会把开关
拨回去并显示错误。

### 7.2. 编辑器：通用字段

- **备注**——你用来辨认它的名字；
- **协议**——创建时可从 vless、vmess、trojan、shadowsocks、mixed（SOCKS 和 HTTP
  共用一个端口；它取代了原来的 socks）和 http 中选择，另外还有 **TUIC**（面板 3.8.0）
  和 **MASQUE**（面板 3.10.0）——关于这两者见 [7.6](#76-需要特殊处理的协议)。
  在网页面板中创建的其他协议的入站，在应用里同样可以查看和编辑；
- **端口**和**监听地址**；
- **已启用**——停用的入站会被保留，但不运行；
- 整个入站的**流量配额**和**到期时间**。“从不”和“选择日期”按钮排成一行，位于日期下方；
- **流量重置**（定期重置流量）——包括月内日期，如果面板支持的话（3.6.0）；
- **禁用 XTLS flow**（仅 VLESS，需要面板 3.7.0）——即使传输层允许，
  也阻止面板向此入站注入 `xtls-rprx-vision`。Vision 在你同一订阅的
  其他入站上照常工作；
- **节点**——已接入节点时，选择把该入站部署到哪台服务器。

**Shadowsocks** 需要选择 **“方式”**：aes-256-gcm、chacha20-poly1305、
chacha20-ietf-poly1305、xchacha20-ietf-poly1305、2022-blake3-aes-128-gcm 和
2022-blake3-aes-256-gcm（默认）。对于 2022 系列方式，应用会自行生成长度合适的
服务器密钥——可以“重新生成”，切换方式时也会重新生成。列表中没有
2022-blake3-chacha20 方式：面板不接受把它用于入站。

**MTProto** 有一个 **“每个 IP 的最大未完成握手数”** 字段（面板 3.10.2、
mtg-multi 1.16.0 及更新）：来自某个地址的新连接，如果该地址已有这么多未完成的握手，
就会被关闭；`0` 表示关闭此限制。

保存时会要求确认——“创建入站？”或“将更改应用到此入站？”——并且不会改动表单里
没有的字段：标签、在订阅中的顺序、从订阅中排除的设置以及流量重置日都保持原样。

### 7.3. 传输与安全

传输层（`streamSettings`）通过结构化字段编辑：传输类型（TCP/raw、WebSocket、
gRPC、HTTPUpgrade、XHTTP、KCP 等）、其参数，以及 TLS 或 REALITY 及其字段——
证书（“证书文件”“密钥文件”）、SNI、指纹、short ID。WebSocket 搭配 TLS 时
默认使用 ALPN `http/1.1`。

编辑器不会提供会让入站失效的传输和安全选项：例如对 MASQUE、XDRIVE 和 TUN，
多余的选项会被隐藏。XDRIVE 的存储在传输设置 JSON 中设置，其安全保持为 None。

一个重要细节：应用把传输层作为活动的 JSON 对象来编辑，因此**它不认识的键不会
丢失**。编辑在网页面板中创建、带有冷门设置的入站，不会把这些设置抹掉。

### 7.4. 嗅探、回退与原始 JSON

- **嗅探**——从流量中识别目标，带类型列表；
- **回退**——按 SNI / 路径转发到其他端口；
- **高级：协议设置（JSON）**——没有做成表单字段的协议设置以原始 JSON 提供。
  客户端单独保存、不会被覆盖：它们在“客户端”标签页管理。

### 7.5. 端口可达性监控

已保存入站的编辑器里有一个 **“监控可达性”** 开关：如果该入站的端口不再响应，
告警会通知你。它属于[告警](#13-告警)，适用于不经反向代理、直接对外暴露的入站。
端口和备注会记在**手机本地**，后台探测会直接叩击那个端口，不经过面板。
之所以这样做，是因为面板往往对手机有防火墙拦截，用它来判断健康并不可靠。

### 7.6. 需要特殊处理的协议

**MASQUE**（面板 3.10.0）：

- **“地址池”** 字段——分配隧道地址所用的前缀，最多一个 IPv4 和一个 IPv6；
  **MTU**（1280 到 65535）以及路径；
- 必须启用 TLS；
- 客户端以邮箱和密码登录，因此 MASQUE 客户端的邮箱不能包含 `:`；
- **MASQUE 没有分享链接**——客户端只能从 JSON 订阅获取连接
  （见 [8.3](#83-把配置交给客户端)）。

**TUIC**（面板 3.8.0）不由 Xray 提供服务，而是由独立的 tuic-server 进程提供。
因此 TUIC 入站没有传输、TLS/REALITY 或嗅探部分：证书、SNI 和 QUIC 选项在
协议设置 JSON 中设置。面板无法在 TUIC 上对单个客户端执行流量限制或 IP 数限制——
流量限制要设在入站本身上。

## 8. 客户端

### 8.1. 列表、搜索与筛选

列表为每个客户端显示：在线圆点、邮箱 / 名称、相对配额的 ↑ / ↓ 流量、实时速率、
到期时间以及最后在线时刻。

**搜索**不只匹配邮箱——还包括备注、sub ID、UUID、密码、auth 字段和 Telegram ID。

**筛选**（带计数徽标的按钮）与网页面板一致：

- 按状态——活跃、已禁用、已过期、已用尽；
- 按分组。

同一区块内的条件之间是“或”的关系，区块之间各自独立收窄结果——与面板中一致。

### 8.2. 创建与编辑

主要字段：**邮箱 / 名称**、**流量配额**（GB）、**到期时间**、**IP 限制**、
**分组**、**备注**、**Telegram ID**、**subId**，以及绑定到一个或多个入站。
如果面板拒绝了绑定或解绑入站，应用会显示错误。

**分组**从面板的分组列表中选择——其中也包括还没有任何人的空分组。你也可以输入
一个新名称：面板会在其列表中显示该分组。分组本身在单独的页面中管理——
见 [8.7 节](#87-分组)。

表单会随所选入站的协议变化：

- **MTProto**：出现 FakeTLS 密钥（带重新生成按钮）和广告标签；
- **WireGuard**：对端的 allowed IPs；
- **AmneziaWG**：**转发端口**——面板路由到该客户端的端口和范围，
  如 `80, 443, 8000-8100`；
- **WireGuard 和 AmneziaWG**：**“Keepalive（秒）”**（面板 3.8.0）——客户端发送
  keepalive 的间隔。`25`（新客户端的默认值）可保持 NAT 开启，让空闲对端在断线后
  恢复；`0` 表示关闭。面板 3.11.0 上的 **AmneziaWG** 客户端还可以填一个范围，
  例如 `15-25`：取值 0 到 65535，下限在前。如果该客户端同时绑定了 WireGuard
  入站，则不接受范围——WireGuard 只接受整数秒；
- **TUIC**：提示单个客户端的流量和 IP 限制在 TUIC 入站上不起作用
  （见 [7.6](#76-需要特殊处理的协议)）；
- VLESS：**flow** 字段。

**续期与流量重置（需要面板 3.7.0）。** 除了熟悉的“每 N 天自动续期”，现在还有：

- **每月续期日**——客户端改为每月在该日期续期，而不是按固定间隔；
  `0` 保持旧模式。当月长度不够时在月末续期；
- **最大续期次数**——自动续期最多触发多少次后就让客户端自然到期；
  `0` 表示不限；
- **客户端自己的流量重置周期**（从不 / 每小时 / 每天 / 每周 / 每月），
  按月时带月内日期。以前重置周期只是入站级设置。

如果客户端在网页面板中设置了每周续期，应用会如实说明，并在普通编辑时保留它；
只有在表单中选择了重置周期或续期日时才会将其关闭。同样，编辑不会丢失 VLESS
反向代理（reverse）。

**设备数限制与设备列表（需要面板 3.7.0）。** **设备数限制**限定多少台设备
可以获取该客户端的订阅；`0` 表示不限。**“设备”**按钮（在已保存的客户端上）
列出已注册的设备：机型和系统、每台设备最后出现的时间，面板 3.8.0 上还有
**“设备指纹”**。设备可以逐个移除，也可以整表清空：这就是给手机解绑的方式——
被移除的设备会在下一次获取订阅时重新注册。

标识符（UUID、密码、subId）由应用在创建时按网页面板相同的格式生成。

**到期时间精确到分钟。** 选好日期后，应用会询问一天中的时刻；没有到期时间的
客户端默认为 23:59。时间按手机所在时区录入——与面板自带的网页表单一致——
字段下方会标注该时区。如果面板设置了自己的时区，旁边会同步显示面板时钟上的
同一时刻，这样面板在海外、管理员在家里，也不用猜到底按谁的午夜算。

### 8.3. 把配置交给客户端

点按客户端会打开“分享”面板：

- **订阅**——一条链接，客户端应用由此获取全部配置并保持更新。会显示二维码，
  并有复制和“分享”按钮；
- **JSON 订阅**——以 JSON 形式提供的 Xray 配置；面板提供时才显示。MASQUE
  连接**只包含在此订阅中**；
- **加密的 Happ 链接**（面板 3.8.0）——“创建加密链接”按钮会从面板获取一条
  `happ://crypt5/…` 链接并附带二维码；可以“重新生成”。只有 Happ 应用能打开它，
  但拿到它的人仍可能还原或分享订阅地址。如果该功能已关闭，应用会告诉你在面板
  哪里启用它：**订阅 → Happ → 订阅链接**，“加密订阅链接”；
- **连接**——各服务器单独的链接；每个都可以展开出自己的二维码；
- **“订阅者视角”**——实时订阅状态（在线、已用配额），与客户端自己的应用
  收到的一模一样。需要面板 3.6.0；如果手机访问不到订阅服务器，这一块会直接省略。

过长、无法生成二维码的链接会不带二维码显示——你可以复制或分享它。带后量子密钥的
链接也是如此：它们的二维码会过于密集。

**编辑**、**删除**、**IP 记录**和 **“重置流量”** 也在这里提供：已用流量从零开始计算，
因配额用尽而被停用的客户端会重新启用。重置前会要求确认。

### 8.4. 批量操作

长按进入选择模式。对选中的客户端可以：

- **启用**或**停用**；
- **调整**（“调整”按钮）——增减天数和 GB 数、设置 flow。在面板 3.8.0 上，
  这里还可以设置 **“设备数限制”**（留空则各客户端限制不变；调低会移除多出的
  已注册设备）和 **“MTProto 广告标签”**（32 个十六进制字符表示设置，`none`
  表示清除，留空表示保持不变；仅限 MTProto 入站）。操作完成后，应用会报告
  改动了多少个客户端，以及跳过了哪些、为什么跳过；
- **重置流量**——需要确认；
- **删除**。

### 8.5. IP 记录

显示客户端从哪些地址、什么时候连接过；多面板时还会显示经由哪个节点。
记录可以清空。

记录为空不是故障：面板只在客户端最后一次连接后保留地址 **30 分钟**，
所以最近没有连接的客户端记录为空——应用也会这样说明。

### 8.6. 导出、导入与清理

- **导出**全部客户端为 JSON——可用于备份或迁移；
- **导入**同样的 JSON；面板会跳过邮箱已存在的客户端；
- **删除未绑定的客户端**——移除没有挂到任何入站的客户端。

### 8.7. 分组

“客户端”页面 ⋮ 菜单中的 **“分组”** 项会打开面板的分组列表——其中也包括还没有
任何人的空分组。每个分组显示其客户端数量和流量：发送、接收和总计。

点按分组会展开其客户端列表，带 ↑ / ↓ 流量和“已禁用”标记；点按客户端会打开
它的分享面板。空分组会显示“此分组暂无客户端。”

**“创建分组”** 按钮用于新建分组；其他操作位于分组自身的 ⋮ 菜单中：

- **添加客户端……** 和 **移除客户端……**——从可搜索的列表中挑选客户端。
  一个客户端只能属于一个分组，因此添加会把它移出原来的分组；它绑定的入站不变。
  被移除的客户端仍保留在面板上——只是不再属于任何分组；
- **重命名**——新名称同时应用到分组及其所有客户端；
- **重置流量**——只清零分组的计数器；客户端自己的流量和限制不变。需要面板 3.4.2；
- **删除分组**——分组消失，其客户端以无分组状态保留在面板上；
- **删除分组内的客户端**——把该分组的所有客户端连同其流量一起从面板删除。
  此操作无法撤销，因此需要单独确认。

分组的流量从上次重置起计算，因此可能小于其客户端流量之和。在面板 3.3.0 上，
分组只显示总流量——拆分为发送和接收是 3.3.1 才加入的。

## 9. 节点（多面板）

如果你用一个主面板加多个节点（若干服务器集中管理），这一节很重要。

### 9.1. 列表与状态

每个节点显示名称、地址、状态、其上运行的面板版本和各项计数。开关用于启用和
停用节点。下拉列表即可刷新。

### 9.2. 添加节点

字段包括：名称、协议（http/https）、地址、端口、基础路径、**节点 API 令牌**、
**“TLS 验证”**以及 **“连接使用的出站（留空 = 直连）”**——连接节点时使用的
出站，从 Xray 配置的出站标签中选择。

“TLS 验证”可取值 `verify`（正常校验）、`skip`（不校验）、`pin` 和 `mtls`。
在 `pin` 模式下会出现 **“证书 SHA-256 指纹”** 字段——节点证书的 SHA-256，
以十六进制或 base64 表示。

从面板 3.6.0 起，节点令牌**不会回读**——面板只报告是否已设置。因此编辑时
令牌留空表示“保持现有值”，填入新值则替换。编辑节点不会重置所选入站的同步。

### 9.3. 双向 TLS（mTLS）

⋮ 菜单中一个独立的 **“节点 mTLS”** 页面（面板 3.4.0 及更新）。它涵盖两件事：

- **复制此面板的 CA**——以便在节点上把它登记为受信任；
- **设置 CA**——此面板作为节点时信任其签发的客户端证书的 CA。

从面板 3.7.0 起，这里还有 **“重新加载主凭据”**：更新后的主面板证书会就地生效，
无需重启面板——以前证书轮换要重启后才生效。

有了 mTLS，节点就不需要 API 令牌。

### 9.4. 更新节点上的面板

可以直接从应用里更新节点上的面板。节点会下载新版本并重启，这比一次列表刷新
要久得多——所以应用会持续轮询节点，直到它报告的版本真正变化，然后才显示结果。

## 10. Xray：出站、路由、DNS

与 Xray 配置有关的一切都在顶栏的 **⋮** 菜单里：**出站**、**路由**、**负载均衡**、
**DNS**、**常规 / 日志**、**Geo 数据自动更新**和 **Xray 配置**。各板块编辑的是
同一份配置的不同部分，每次都整体保存配置——你没有碰过的相邻部分会原样保留。

出站、规则、负载均衡和 DNS 服务器的编辑器都有 **“保存”** 按钮——改动会立即发送到
面板。系统返回键回到列表。如果标签为空或已被占用，表单会滚动到出错的位置。

**更改何时生效。** 面板 3.3.1 及更新版本会自行应用已保存的配置：能热更新的就地
生效，只有别无他法时才重启 Xray。应用会提示“已保存并应用”，无需手动重启任何东西。
例外是编辑出站订阅：之后应用会提示“已保存——重启 Xray 以生效”（刷新、移动和删除
订阅则由面板在 30 秒内自行应用）。在面板 3.3.0 上，更改要在 **Xray 重启后**
才生效——按钮在仪表盘上。

### 10.1. 出站

出站列表，显示各自的标签、协议和地址。第一个是默认路由，并有相应标注。可用操作：

- **创建和编辑**出站：协议、地址、端口、凭据、传输，外加**目标策略**
  （从 `AsIs` 到 `ForceIPv4`）和“发送经由”。协议中包括 **AmneziaWG**（面板 3.8.0）；
  对于 **Hysteria** 和 **MASQUE**（包括基于 MASQUE 的 WARP），可以设置传输和 TLS。
  TLS 有一个 **“使用系统 CA”** 开关（面板 3.10.0）：用服务器操作系统的 CA 存储
  而不是 Xray 内置的根证书来校验服务器——私有 CA 需要它；
- **排序**——用上 / 下箭头；顺序决定哪一个成为默认路由；
- **删除**；
- **从 `vless://` 链接导入**；
- 以 JSON **导入和导出**整个列表。

### 10.2. 测试出站

每个出站都有 **“测试”** 按钮，带模式选择器：

| 模式 | 测什么 |
|---|---|
| **TCP** | 连接层面的可达性与延迟 |
| **HTTP** | 经代理发起完整请求；还会报告出口 IP 和国家 |
| **真实延迟** | 包含隧道建立的总时长——最接近真实体验 |

使用 HTTP 和“真实延迟”模式时，结果旁边还会显示 IP、国旗，以及出口经由
**WARP** 时的标记。探测所用的 URL 在面板一侧设置。

### 10.3. 出站订阅

面板可以自行从订阅地址拉取别人提供的服务器列表，并将其作为出站并入配置。
该板块从“出站”页面的 **⋮** 菜单进入。

每个订阅可配置：

| 字段 | 含义 |
|---|---|
| **订阅地址** | 面板从哪里获取列表 |
| **备注** | 你用来辨认它的名字 |
| **标签前缀** | 例如 `hk-`，用于在路由中区分它的服务器 |
| **更新间隔** | 面板多久重新读取一次该地址 |
| **已启用** | 临时关闭而不删除 |
| **置于手动出站之前** | 把它的服务器排到你自己的前面——之后其中一台可能成为默认路由 |
| **允许私有地址** | 允许指向本地 / 局域网地址的 URL；出于安全默认关闭 |
| **允许不安全的 TLS** | 用于自签名证书的来源 |

操作：**预览**（保存前，面板先拉取并解析该地址，显示找到多少服务器、
都是什么标签）、**立即刷新**、**全部刷新**、排序和删除。

来自订阅的服务器会在“出站”页面单独成块，标题为“来自出站订阅”。它们可以像普通
出站一样**测试**，也可以用于路由规则和负载均衡，但**不能直接编辑**：每次订阅刷新
面板都会重新生成它们，任何编辑都会被覆盖。请通过订阅本身来修改。

### 10.4. 路由

**路由**板块包含：

- **“路由规则”**——按域名、IP、端口、协议、入站；每条规则指向一个出站或一个
  负载均衡，流量将被发往那里。规则可以启用 / 停用、重新排序、导入和导出。
  规则的备注在列表中可见，在面板 3.8.0 上还可以编辑——“备注（仅面板可见）”字段，
  最多 200 个字符；
- **“路由策略”**——`AsIs`、`IPIfNonMatch` 或 `IPOnDemand`；
- **“测试路由”**按钮——见 [10.6](#106-路由测试)。

未匹配任何规则的流量走列表中的第一个出站——见 [10.1](#101-出站)。

内部统计规则（`api`）受保护、不可停用——没有它流量统计会失灵。

如果在“常规 / 日志”中设置了路由脚本（见 [10.8](#108-常规设置与日志)），
该页面会提示 Xray 会忽略这些规则。

### 10.5. 负载均衡与观测器

负载均衡有自己的菜单项 **⋮ → 负载均衡**。它们是出站的分组，Xray 按策略从中
挑选出站。负载均衡编辑器：

- **标签**——路由规则引用的名字；
- **策略**——`random`、`roundRobin`、`leastLoad` 或 `leastPing`；
- **选择器（逗号分隔）**——组内出站的标签或标签前缀；
- **回退**——组内没有合适的出站时使用的出站。

`leastLoad` 和 `leastPing` 策略，以及带回退的 `random` 和 `roundRobin`，都需要
一个探测出站的**观测器**（observatory）。应用会自行创建和移除它——以前没有观测器时
Xray 会以“not all dependencies are resolved”启动失败。**“观测器”**区块（面板 3.10.0）
设置探测方式：“探测 URL”（必须返回 HTTP 204）、“探测间隔”、“探测超时”、
“采样数量”、“HTTP 方法”及其他参数。被观测的出站列表跟随负载均衡的选择器。
没有观测器时，页面会如实说明：“当前没有活动的连接观测器”。

该页面用它自己的 **“保存”** 按钮保存——有未保存的改动时它才可用。更改策略不会
重置 `leastLoad` 的设置。

### 10.6. 路由测试

这个工具回答“这个地址会走向哪里”。输入域名或 IP，可选端口和网络类型，
**选择一个入站**——然后你会得到最终出站、负载均衡链，或“默认出站”的判定。

选择入站是必选项而非可选项：几乎所有路由规则都以入站为条件，没有它路由器
无法判断。该测试只对本地入站有效；主面板没有针对节点入站的路由规则，
所以对它们的结果没有意义。

### 10.7. DNS

DNS 部分的编辑器：服务器（普通和条件）、查询策略，以及静态 hosts 条目。

从面板 3.10.0 起，DNS 可以使用 **“Lua 脚本”**——指向一个包含 `HandleDNSQuery`
函数的 `.lua` 文件的路径：脚本会应答每一个查询，并自行联系服务器。为此服务器有一个
**“ID”** 字段——脚本据此选择服务器的名字。如果文件不存在或有错误，Xray 将无法启动。

保存服务器时会保留其 ID、标签、客户端 IP、预期 IP、“跳过回退”和超时设置。

### 10.8. 常规设置与日志

**常规 / 日志**板块：日志级别、日志访问参数、统计以及其他核心常规设置。

这里（面板 3.10.0）还有 **“路由脚本”**：指向一个包含 `HandleRoute` 函数的
`.lua` 文件的路径。此后由脚本为每个连接选择路由，Xray 会忽略**全部**路由规则，
包括面板的 `api` 规则。请在脚本中自行把 `api` 入站发往 `api` 出站，否则流量统计
和客户端的实时变更都会停止。如果文件不存在或有错误，Xray 将无法启动。

### 10.9. Geo 数据自动更新

仪表盘上的 Geo 数据库按钮（见 [6.6](#66-面板版本与-geo-数据库)）是
**现在就手动拉取**。**“Geo 数据自动更新”**板块配置的是同一件事的**定时执行**：
Xray 自己下载列出的文件并重新加载，无需重启。需要面板 3.7.0。

- **计划**——五段式 cron 表达式，例如 `0 4 * * *`（每天凌晨 4 点）。
- **通过出站下载**（可选）——列表来自配置里的出站标签。留空表示走常规路由。
- **文件**——文件名和它的获取地址。URL 必须是 **HTTPS**，文件名要像
  `geosite_custom.dat` 这样的普通名字，不能带路径。

保存前应用会检查这三项约束，不合规的组合不会被放行。删掉最后一个文件会把
整个计划块从配置中移除——没有文件的计划毫无意义。

还有一条约束来自 Xray 自身：**文件必须先在面板的 `bin` 目录里存在过一次**，
否则没有东西可更新——所以先通过仪表盘按钮或手动放入，之后计划会持续保持它
最新。路由规则以 `ext:geosite_custom.dat:category` 这样的形式引用此类文件。

### 10.10. 完整 Xray 配置

如果某个需要的字段任何表单里都没有，可以直接以文本编辑配置——整份配置，
与面板的 Xray 配置页相同的 JSON。旁边的出站测试 URL 也在这里设置。
保存时会要求确认：面板中的配置会被替换并立即应用。面板 3.3.1 及更新版本会自行应用——
能热更新的就地生效；在 3.3.0 上需要重启 Xray。

## 11. 面板管理

**面板管理**板块（**⋮** 菜单）汇集面板自身的设置。

- **管理员账户**——修改登录名和密码。需要输入当前凭据。修改后你的 API 令牌
  继续有效，但其他浏览器会话会被登出。
- **API 令牌**——面板的令牌列表：启用、停用、删除、创建。新令牌的值只显示
  **一次**——请立刻复制。删除某个令牌会立即切断所有使用它的应用。从面板 3.7.0 起，
  创建令牌时可以选择它的**范围**：
  - **Admin（完全访问）**；
  - **Monitor（只读）**——服务器状态和指标历史；
  - **Node sync（节点同步）**——中心面板所需的权限：入站、客户端、重启 Xray；
  - **Node administrator（节点管理员）**——节点同步权限，并可启动面板更新；
    需要面板 3.11.0。

  还可以设置可选的**有效期（天）**。列表中令牌名称下方会显示范围和到期日期，
  已过期的令牌会被标出。应用本身需要 `admin` 令牌：使用其他范围时，某些板块将无法
  工作。之前签发的令牌都是 `admin` 范围——它们的行为不变。
- **IP 限制白名单**（需要面板 3.7.0）——以逗号分隔的地址和子网（IP 或 CIDR），
  IP 限制永远不会统计它们，也不会封禁它们。在许多人共用一个地址的场景下需要它：
  共享的办公室出口或 CGNAT 运营商否则会耗尽某个客户端的限制并导致其被封锁。
- **订阅**——**公告**文本（`subAnnounce`），在订阅信息页以横幅显示。
- **邮件（SMTP）**——面板邮件的发件地址和名称。地址留空则回退到 SMTP 用户名。
  当中继的登录名不是邮箱地址时这一点很重要：没有有效的 `From`，Gmail 等
  严格的收件方会拒收。需要面板 3.6.0。
- **通知**——**“出站故障阈值”**：连续多少次探测失败后，面板才发送出站不可达的
  告警。`1` 表示旧行为，第一次失败就告警。它有助于在链路不稳时避免误报刷屏。
  需要面板 3.6.0。
- **重启面板**——重启面板服务本身；应用的连接会中断几秒钟。

## 12. 备份

**备份 / 恢复**板块。

- **备份到文件**——应用拉取面板数据库并询问保存位置。文件名由面板决定：SQLite 为
  `x-ui.db`，PostgreSQL 为 `x-ui.dump`。
- **从文件恢复**——选择一个文件；面板用自己的数据库引擎导入它。在面板 3.8.0
  及更新版本上，面板会在导入后自行重启；应用会等到它重新响应，并报告
  “已恢复——面板已重启并恢复运行”。如果一分钟后面板仍无响应，应用会如实说明。
  在较旧的面板上，导入后会重启 Xray。

该数据库装着**一切**：面板设置、入站、客户端和 Xray 配置。因此备份是迁移到
另一台服务器最快的方式——同样因此，它是一份应当视同机密对待的文件。

API 令牌同样来自备份：如果其中没有本应用的令牌，恢复后需要重新连接。应用会在
确认对话框中就此提醒你。

## 13. 告警

### 13.1. 工作原理

告警**完全在本地**。应用自身大约每 30 分钟轮询一次已保存的面板并发出系统通知。
不涉及任何外部推送服务：你的数据和面板地址都不会外流。代价是告警要到下一次
检查时才出现，而不是在同一秒出现。

可达性检查是 **TCP 端口层面**的，不走面板 API。原因很简单：面板往往对手机
有防火墙拦截，它不可达说明不了服务的健康状况。默认探测 **443 端口**——
通常的公开入口。

为了避免虚惊，不可达告警只在**连续两次检查失败**后触发；认证错误（401）
不算作不可达。

### 13.2. 告警类型

| 告警 | 何时触发 |
|---|---|
| **客户端已到期** / **即将到期** | 到期时间已过，或距到期不足配置的天数 |
| **流量即将用尽** | 已用超过配置的百分比 |
| **面板不可达** | 配置的端口无响应 |
| **入站不可达**（一个或多个） | 标记为监控的入站的端口无响应 |
| **Xray 已停止** | 核心没有在运行 |
| **节点离线** | 节点掉线 |

通知分为**两个系统渠道**——客户端类和基础设施类。这样你可以在 Android 设置里
静音客户端类的絮叨，同时保留服务器告警。每条通知都带有触发日期和时间，
几小时后看到它时，也能判断问题是否还在当下。

### 13.3. 配置

在**设置 → 面板告警**下：

- **启用**开关——客户端到期、流量限制、入站和节点的可达性（Android 13+ 上应用会
  请求通知权限）；
- **到期前天数**——提前多久提醒（默认 3）；
- **流量阈值（%）**——用到多少时提醒（默认 90）；
- **面板端口**——探测可达性用哪个端口（默认 443）。

单个入站从各自的编辑器加入监控——见 [7.5](#75-端口可达性监控)。

## 16. 隐私与安全

**应用连接到哪些地方。** 只连接你自己输入的地址：你的面板，以及在把订阅
交给客户端时的订阅服务器。此外，标准版还会访问所选更新通道对应的应用 releases
页面以检查更新。应用内没有任何分析、广告或跟踪器。

**F-Droid 版完全不接触我们的基础设施**——它连更新检查都没有。说实话的
副作用是：我们无从知道有多少人通过商店目录使用这个应用。

**你的数据如何存储。** 连接配置（面板地址和 API 令牌）存放在 Android 的
加密存储中：值以 AES-256-GCM 加密，密钥以 AES-256-SIV 加密，主密钥保存在
Android Keystore 里。此外，进入应用还可以用密码和生物识别来锁定。

应用请求的**权限**：

| 权限 | 用途 |
|---|---|
| 互联网和网络状态 | 与面板通信 |
| 通知 | 本地告警 |
| 生物识别 | 指纹 / 面容解锁 |
| 安装软件包 | 仅标准版——用于安装更新；F-Droid 版没有该权限 |

**请记住。** 具有 `admin` 范围的 3x-ui API 令牌是完整的管理员权限。“允许自签名 TLS”
模式会关闭证书校验，只适用于你自己的面板。加密的 Happ 链接只能让订阅地址不被
随手看到：拿到链接的人可以还原出地址。

## 17. 面板版本兼容性

**最低要求的面板版本是 3.3.0**：面板从这个版本开始接受整个应用所依赖的
API 令牌认证。在这个版本的面板上，应用可以运行，但有些能力是更晚的面板
版本才加入的。应用已在**最高到 3.11.0（含）**的面板上测试过。

| 能力 | 需要的面板版本 |
|---|---|
| API 令牌登录、仪表盘、入站、客户端及其分组、订阅、Xray 配置 | 3.3.0 |
| 出站订阅、分组流量拆分为发送和接收、保存 Xray 更改后无需手动重启即可生效 | 3.3.1 |
| 节点与 mTLS、客户端 IP 记录、客户端导入导出、入站实时速度、在线客户端按服务器拆分 | 3.4.0 |
| 客户端批量操作、VLESS 加密密钥生成 | 3.4.1 |
| 客户端分组流量重置 | 3.4.2 |
| 客户端实时速度、出站测试、目标策略、路由测试、订阅公告、MTProto 和 WireGuard 客户端字段 | 3.5.0 |
| SMTP 发件设置、出站故障告警阈值、“订阅者视角”状态、只写节点令牌、按月的流量重置日 | 3.6.0 |
| 每月按日续期、最大续期次数、客户端自己的流量重置周期、设备数限制与设备列表（HWID）、AmneziaWG 转发端口、API 令牌范围与有效期、IP 限制白名单、“禁用 XTLS flow”、重新加载主面板的 mTLS 凭据、Geo 数据自动更新 | 3.7.0 |
| WireGuard 和 AmneziaWG 客户端 keepalive、加密的 Happ 链接、批量设置设备数限制和 MTProto 广告标签、设备指纹、AmneziaWG 出站、编辑路由规则备注、TUIC 入站、恢复备份后等待面板重启 | 3.8.0 |
| MASQUE 入站与 JSON 订阅、“使用系统 CA”、用于 DNS 和路由的 Lua 脚本、DNS 服务器 ID、观测器设置、创建使用 2022 密钥的 Shadowsocks 入站 | 3.10.0 |
| MTProto 的“每个 IP 的最大未完成握手数”（需要 mtg-multi 1.16.0） | 3.10.2 |
| AmneziaWG 客户端的 keepalive 范围、“Node administrator（节点管理员）”令牌范围 | 3.11.0 |

面板 3.9.0 没有为应用带来新功能——在 3.8.0 上能用的一切在它上面同样可用。

**建议很简单：用最新的面板。** 这样应用的每个板块都可用，沿途也能获得面板
自身的修复。

如果面板版本低于某个板块所需，应用**不会把它隐藏**——而是给出说明：
你的面板版本不支持此功能，请更新面板。这样你能看到功能的存在，也知道该怎么做。

## 18. 故障排除

**“意外响应”或解析错误。** 应用收到的东西不是 JSON。最常见的原因是面板地址
缺少秘密路径（`webBasePath`），或者反向代理拦截了请求。从浏览器复制完整地址
来核对。

**证书错误。** 在连接设置里打开“允许自签名 TLS”——但只对你自己的面板。

**“你的 API 令牌已失效”。** 令牌在面板里被删除或禁用了。新建一个再连接；
其余项会由已保存的配置自动填好。

**某个板块提示面板不支持该功能。** 面板版本低于要求——见[第 17 节](#17-面板版本兼容性)。
从仪表盘更新它。

**Xray 的改动没有生效。** 在面板 3.3.1 及更新版本上，保存后会立即应用。如果保存后
应用提示“已保存——重启 Xray 以生效”（编辑出站订阅之后会这样），或者面板低于 3.3.1，
请用仪表盘上的按钮重启 Xray。

**设置负载均衡或脚本后 Xray 无法启动。** 检查 DNS 或“常规 / 日志”中指定的 `.lua`
文件是否存在且没有错误——否则 Xray 无法启动。`leastLoad` 和 `leastPing` 负载均衡
（以及带回退的 `random` 和 `roundRobin`）需要观测器——应用会自行添加，但如果配置是
手动编辑过的，请检查“观测器”区块，见 [10.5](#105-负载均衡与观测器)。

**收不到告警。** 检查设置里是否已启用、Android 是否授予了通知权限、电池优化
是否在杀掉应用。记住检查大约每 30 分钟跑一次，不可达要在连续两次检查失败后
才上报。

**路由测试总是“默认出站”。** 没有选择入站——规则几乎都以它为条件。
对节点入站而言结果没有意义：主面板没有针对它们的路由规则。

**应用更新迟迟不到。** F-Droid 版的更新只经由商店目录，会在发布后一两天
出现——那是他们构建服务器的节奏，不在我们的控制之内。标准版请检查所选的
[更新通道](#24-更新通道)，然后按“检查更新”。
